The honest truth about content security

Don't just hope your material stays private

No web platform can guarantee against a photo of a screen, an external camera, or a screenshot at the operating-system level. Anyone who promises otherwise is selling something.

So EduVault is built around that honest limit — controlling what can actually be controlled: private storage that only our processing can reach, authorization checked on every request, and a personalized watermark that makes any leak traceable back to the exact session it came from.

Protected where it's possible. Traceable everywhere else. That's the promise — and it's the only one worth making.

What's inside

A few protections, explained

Each control comes with a clear rationale — what it does, and why it's built that way.

Watermarking

Every page carries the reader's identity

Material opens with the student's name, ID, and organization rendered directly onto each page. The watermark is generated server-side, so there is nothing on the client to strip, crop, or edit.

Some will still try to share a screenshot. That's exactly why the watermark exists: a leak from any session can be traced back to the person it was assigned to.

Access control

Only assigned students, on approved files

Only students explicitly assigned to a batch or file, in an approved organization, can open it. Every request is checked — there is no ambient access and no shareable link to pass around.

Disable a student or a file and access stops immediately. Staff can revoke access all day; permanent deletion stays reserved for organization admins.

More than a viewer

Everything works together, day to day

Upload, assign, read, revoke — the whole loop runs in one place, with the security model baked into each step rather than bolted on afterwards.
